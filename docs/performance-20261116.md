# 再描画・会話保存の負荷削減

2026年11月16日。前回の未使用処理・重複整理コミット `1037487` を起点にした開発変更です。

## 確認した負荷と変更

### 内容が変わっていない画面の再描画

AI画面への再表示などで `draw()` が呼ばれると、会話に変更がなくても `host.innerHTML` を置き換え、会話200件と入力欄を作り直していました。

実際に生成したHTMLと、会話・案の版・作業段階・表示対象が直前と一致するときはDOMの置き換えを省きます。会話の件数や短いハッシュだけで判定せず、同じ件数で本文が変わった場合や接続状態・操作ボタンが変わった場合には更新します。表示後のコールバックは引き続き呼びます。入力欄、フォーカス、選択範囲、スクロール、開いた詳細を保持します。

送信中の操作制限や保存状態などを部分的に書き換えた場合は、比較用のHTMLを破棄します。送信前の確認を取り消した後に無効状態が残らないことを、既存の回帰テストで確認します。

工程図の読取操作を持つ画面は、既存の再配置・サイズ調整を維持します。表示状態を初期化する `resetDisplay()` も明示的に再描画します。

比較用に保持するHTMLは直前の1件だけで、上限は512K UTF-16コード単位です。それより大きい画面は通常どおり描画し、会話や説明を切り詰めません。画面の `dispose()` で保持内容を解放します。この方式は再描画時間と引き換えに表示中のメモリを少し使用するため、測定では使用中・終了後の両方を確認します。

### 変更がない会話の保存確認

変更がなくても会話全体をJSONで複製し、内容比較用にもう一度複製していました。変更なしの場合は、現在の内容を一度文字列化して前回と比較し、複製・再解析・IndexedDBへの書き込みを省きます。変更通知だけに依存せず、通知されていない入力変更も検出します。

変更がある場合は、最初の非同期処理より前に独立した保存用スナップショットを作ります。編集か表示位置の変更かを判定するときは必要な外側のオブジェクトだけを作り、会話本文や生成コードを再複製しません。保存後にも現在の内容と照合するため、保存中の追加入力は未保存として残し、次の保存へ引き継ぎます。

会話の選択情報を復旧する保存でも、非同期処理中の追加入力を再確認します。完了・固定・保存期限・旧会話の形式・権限確認・容量制限・競合時の拒否は維持しています。

## 測定条件と範囲

`tools/benchmark-toolkit.cjs` を変更前後のソースへ適用します。専用のEdgeコンテキスト、1440×1000、架空のフィールド500個、会話200件、手編集ファイル10本、保存内容581,352 bytesを使います。ウォームアップ1回を除き9回の中央値を比較します。

```powershell
node tools/benchmark-toolkit.cjs --source-root <変更前チェックアウト> --out <変更前.json>
node tools/benchmark-toolkit.cjs --out <変更後.json>
```

実際の表示処理とIndexedDBを使い、読み戻した保存内容の一致と会話件数を確認します。実AI・実kintoneへの通信は行いません。保存用のcaptureは架空のスナップショットを返すため、運用時の `exportSession()` 自体の時間やネットワーク待ち時間は測定に含みません。

再描画5回は描画関数の同期処理、変更なし保存10回は保存確認の連続実行です。画面表示とタブ往復は2回のanimation frame待機を含みます。使用中・終了後のJSヒープはいずれもGC後の値で、ピークメモリではありません。初回IndexedDBオープンなど待機時間の変動を含む値と、処理回数の削減を区別します。

## 回帰確認

- 変更なし保存のJSON再解析・複製を省き、実際の書き込みを増やさないこと。
- 保存中の追加入力、連続した保存要求、表示位置のみの変更、完了済み会話の再編集。
- 選択情報の復旧中に入力しても、内容と未保存状態を保持すること。
- 同じ画面の再描画でDOM・フォーカス・選択・スクロールを保持し、本文・接続状態の変更は反映すること。
- 保持上限を超える長文も省略せず表示し、明示的な表示初期化は再描画すること。

全146テストファイルをユーザースクリプトと拡張機能用に変換したランタイムの両方で実行し、それぞれ2,038件成功、失敗・タイムアウト0件でした。生成済みユーザースクリプトと分割ソースの一致も確認しました。

初回の全体検証では、送信前確認を取り消した後にボタンの無効状態が残るケースを既存テストが検出しました。部分更新時の比較用HTML破棄を追加し、同じ見た目でも会話や案の版が変われば更新する検証を補強した後、全146ファイルを両形式で再実行して成功しています。取消、連打、古い案への操作の防止も含みます。

回帰テストと前後の測定結果は作業記録に保存します。この変更は開発元へ統合し、公開版や導入済み拡張機能の更新とは分けて扱います。

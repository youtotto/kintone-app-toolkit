# 未使用処理・重複の整理と性能の基準値

2026年11月16日。公開版2.3.7と文書更新コミット `c754b21` を起点とした開発変更です。

## 変更した範囲

- 本体内に定義以外の参照がない旧表示用の定数・関数16件を削除しました。削除した関数だけが使っていた理由一覧も含みます。保存データの読み取りや互換処理は変更していません。
- HTMLテキストのエスケープ6か所と、同じnull・undefinedの扱いを持つJSON複製4か所を `src/release-utils.js` に集約しました。入力の扱いが違う複製関数は、一律に置き換えていません。
- 公開本体から呼ばれていない使用量診断を生成対象から外しました。`src/release-usage-diagnostics.js` と検証用のレポート・テストは保持し、検証用予算機能を使うテストで明示的に読み込みます。
- ブラウザーの小さなテストでソースを直接読む場合も、共通処理を先に読み込みます。

`cloneJson` は従来どおりJSON形式で複製します。日付、undefined、非有限数、循環参照などの扱いが異なる `structuredClone` への置き換えは行っていません。HTMLの表示文字と引用符のエスケープも従来どおりです。

本体はLF改行で比較して **2,247,805 → 2,217,471 bytes**、30,334 bytes（約1.35%）減りました。これは圧縮前の本体サイズです。

## 性能測定

`tools/benchmark-toolkit.cjs` で、専用のEdgeコンテキストと架空データを使います。ページと既知のアイコンはローカル応答に置き換え、その他の通信は遮断します。実kintoneのデータや実AI、会員の認証情報は使いません。

```powershell
node tools/benchmark-toolkit.cjs --out <測定結果.json>
node tools/benchmark-toolkit.cjs --source-root <比較対象のチェックアウト> --out <変更前.json>
```

ブラウザー試験と同じPlaywright・Edge環境を使います。[試験環境](test-setup.md)を参照してください。ほかのブラウザー試験・ビルドを同時に実行せず、同じ端末・ブラウザー版・画面寸法・サンプル数で比較します。

今回の条件はEdge 157.0.4341.60、1440×1000、フィールド500個、会話200件、手編集ファイル10本、保存内容581,352 bytesです。ウォームアップ1回を除き、毎回新しいブラウザーコンテキストで9回測定した中央値です。元の配布物の改行差が比較に混ざらないよう、読み込み時にLFへ揃えています。

| 測定対象 | 変更前 | 整理後 |
| --- | ---: | ---: |
| 本体の挿入・コンパイル・初期化 | 20.4 ms | 19.3 ms |
| パネル作成・Fields表示 | 155.0 ms | 157.4 ms |
| 長い会話の初回表示 | 105.3 ms | 101.6 ms |
| FieldsとAI画面の往復 | 150.0 ms | 149.9 ms |
| IndexedDBへの初回保存 | 86.1 ms | 86.2 ms |
| 下書き変更後の保存 | 5.6 ms | 5.8 ms |
| 変更なしで保存確認 | 2.2 ms | 2.3 ms |
| 保持されたJSヒープ | 3,145,796 bytes | 3,128,564 bytes |

画面表示は描画を待つ2回のanimation frameを含みます。本体はブラウザーへ転送した後で挿入時間を計測し、自動操作の転送時間や自動起動時のAPI取得を含めません。パネル・会話は取得済みデータを使った実際の表示処理です。保存は実際のIndexedDBを使い、読み戻しの内容一致と会話200件の表示を確認します。ヒープは履歴・画面のdispose後にGCを実施した値で、ピークメモリではありません。

**この結果から体感速度の改善は主張しません。** 数msの増減があり、今回の主な成果は不要コードの削減と共通化です。この基準値を、今後の再描画・保存処理の改善と比較できます。実ネットワークの待ち時間、実AIの応答時間、利用者の端末すべてでの性能は対象外です。

## 検証方法

HTMLの特殊文字・日本語・改行、JSON保存の正規化、複製後の編集分離、循環参照・BigIntの拒否、フィールド名の保持を確認するテストを4件追加しました。既存の相談・作成・反映・復元・会話保存を含む全144ファイルが、ユーザースクリプト本体と正式ビルド処理で変換した拡張機能本体の両方で成功しました。それぞれ2,028件成功、失敗・時間切れ0件、144ファイルの結果が一致しています。

最初の全件実行では、2ファイルで検証準備に起因する失敗がありました。VMでソースを単独読込する試験にも共通処理の読込を追加し、プロセス図の試験用Mermaidは既存の正式配布物から再利用しました。製品コードは変更せず、この2ファイルを両形式で再実行して成功を確認しています。

この段階では配布版の更新や公開、インストール済み拡張機能の置き換えは行いません。
